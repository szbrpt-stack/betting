# S2S Sigma — Mobile event-first product contract (v0.1)

Status: design proposal on feature/nba-engine. No production migration, no live AI provider connection.

## Goal
One event anchors all predefined questions. User selects date -> event -> question -> evidence-backed answer. Reuse templates for every NBA event.

## Mobile navigation
1. Today: date picker, event list (away, home, tipoff with timezone, venue, status, source timestamp), loading/empty/error states.
2. Event detail: matchup header, recent form, source freshness, question chips: recent balance, offense/defense, pace, home/away split, availability, player performance, matchup viability.
3. Analysis: direct answer first, then evidence and calculations, comparison chart, uncertainty and limitations, source links, refresh time.
4. Saved analyses: keyed by event + question + parameters + cutoff + evidence revision. Clearly mark stale.

## Suggested API contract (versioned)
GET /api/v1/events?date=YYYY-MM-DD&timezone=America/Bogota
GET /api/v1/events/{event_id}/questions
POST /api/v1/analyses
Request: {event_id, question_id, parameters:{window:10,threshold:null}, as_of:"ISO8601"}
Response: {analysis_id,event_id,question_id,question_text,status,as_of,generated_at,
 answer:{headline,summary,viability_level},
 metrics:[{key,label,value,unit,scope,sample_size,method,evidence_ids}],
 comparisons:[{metric,home,away,unit}],
 visuals:[{type:"bar|line|table",metric_keys:[]}],
 evidence:[{id,source_name,url,published_at,retrieved_at,observed_at,entity,scope}],
 limitations:[string],uncertainty:{status:"not_quantified|validated",interval:null,calibration_reference:null},
 quality:{completeness,conflicts,freshness,grade},
 audit:{formula_version,source_snapshot_ids,cutoff,model_version}}
All output is source-linked. Unknown fields are null, never fabricated.

## Mandatory validation
- Event identifiers and teams must match the same game, season and venue; schedule dates carry timezone.
- All last-N metrics use N *completed eligible games* before the analysis cutoff, with home/away filters.
- No use of post-tipoff facts in pregame answers.
- Points per game, offensive rating per 100 possessions and pace are distinct metrics; never compare them as if equivalent.
- Missing injuries and unconfirmed lineups are UNKNOWN, not healthy or zero impact.
- Separate observed hit rate from future probability; future probability only with out-of-sample calibration, interval, and documented sample size.
- Report sample coverage (e.g. 8/10) and contradictory sources; with insufficient evidence return 'insufficient_evidence'.
- Source licensing, retention and access controls are gates for automated ingestion.

## Uncertainty reduction strategy
1. Retrieval: cross-check primary official box scores when permitted; track provenance and timestamps.
2. Measurement: sample size, missingness, season, venue, pace normalization, opponent quality.
3. Estimation: shrink small samples toward current-season baselines, never use stale roster-era data by default.
4. Prediction: rolling time-based backtesting; calibration and coverage of prediction intervals, plus error by team and matchup type.
5. Decision: abstain when evidence quality or calibration is inadequate. Explain which missing observation would most change the answer.
6. Monitoring: compare postgame outcome to pregame estimates without leaking results into historical pregame snapshots.

## Current repository constraints
- backend-data-engine/main.py is a FastAPI aggregator for football matches with /api/v1/full-catalog and /api/v1/sync; do not repurpose or alter these endpoints in-place.
- nba_engine/current.py is an offline heuristic that explicitly returns win_probability=None.
- No mobile source tree was found in the inspected feature branch. This document defines the interface contract; it does not claim to deploy a mobile UI.
- ChatGPT consumer accounts are not an unrestricted free backend API. Keep model provider behind a replaceable adapter; use authorized provider access and rate limits.

## Delivery sequence
A. Implement separate read-only event/question endpoints and typed mock fixtures with test coverage.
B. Implement mobile screen against mock responses, including empty/stale/insufficient-evidence states.
C. Integrate licensed schedule and per-question evidence retrieval; record exact source provenance.
D. Connect deterministic statistical engine and validate on real current-season samples.
E. Enable AI explanation adapter only after structured evidence checks; audit cost and latency.
F. Pilot NBA, then generalize to other competitions via sport-specific question packs.

No statistical claims or game data are generated by this design document.
